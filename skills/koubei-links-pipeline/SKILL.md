# Koubei Pipeline — 口碑链接整理与核实流水线

## Overview

对已有的懂车帝口碑链接做完整整理与核实，最终把结构化数据回填到腾讯文档表格。标准链路：  
读表格拿链接 → 浏览器分批打开 → 无头 Chrome 复用登录态下载 HTML 快照 → 从 `__NEXT_DATA__` 提取标题/评分/发布日期 → 写回表格 → 评分区间核实(标红) → 图片核实(R1 基础规则 **含人物按严重程度分级** / R2 车身外观 vs 汽车之家官方图(口碑中的车身外观是否符合官方车型) / R3 口碑内颜色统一 = **内饰图片统一** + **车身颜色统一**(车身漆面色 ≠ 内饰氛围灯/反光) / R4 图文颜色一致 = **图片颜色 vs 文章写的外观/内饰颜色**，不符标蓝) → 重复核实(**发布的文章之间是否有重复**：同账号+车型 / 标题前30字强相似 / 正文强相似，链接完全相同直接判重，输出到「是否重复」列) → 参数核实(**文章中的各种参数是否与官方一致**：价格/续航/油耗/尺寸/配置等，不符标出写回备注)。

## 来源判断：懂车帝 vs 汽车之家（**先分清，两条路完全不同**）

| 来源 | 链接形态 | 抓取方式 | 登录态 |
|---|---|---|---|
| **懂车帝** | `m.dongchedi.com/koubei/…` | 有头 Chrome + CDP（见 Step 3） | **必须登录** |
| **汽车之家** | `k.autohome.com.cn/detail/view_*.html`<br>`k.m.autohome.com.cn/detail/share_*.html` | **纯 urllib 直连即可**（见 Step 3B） | 不需要 |

**汽车之家三步走（2026-09 验证通过，零依赖）**：
1. 移动链接换 PC：`k.m.…/detail/share_` → `k.autohome.com.cn/detail/view_`（其余 ID 段不变）
2. 请求头：桌面 Chrome UA + `Referer: https://k.autohome.com.cn/`，响应需 gzip 解压
3. 字段位置（HTML 正则，无需 `__NEXT_DATA__`）：
   - 标题 `<h1 class="title">` / 车系 `.main-series` / 配置 `.main-spec`
   - 发布日期：正则 `(\d{4}-\d{2}-\d{2})\s*首次发表`
   - 分项评分：`<h1>小点名<div class="athm-star">…<span class="star-num">N</span>`（7 项：空间/驾驶感受/续航/外观/内饰/价格政策/智能化）
   - 正文：`.kb-item-msg`（按小点逐段）；昵称：`<title>` 按 `_` 拆取**倒数第 3 段**
   - 总分：分项求平均（汽车之家 5 分制，两位小数）
   - 脚本：`scripts/extract_autohome.py`（本次任务产出，已含缓存与移动链转换）

> **汽车之家没有 `__NEXT_DATA__`，别套懂车帝的解析器。**

## 环境与前置

- Chrome：先探测 `C:\Program Files\Google\Chrome\Application\chrome.exe`，其次 `%LOCALAPPDATA%\Google\Chrome\Application\chrome.exe`（本机在 Program Files）
- Chrome 版本提示：Chrome 127+ 的 Cookie 使用 **App-Bound Encryption**（值前缀 `v20`），密钥由系统级服务托管，见 Step 3 的应对方案
- 腾讯文档工具：`tencentdocs.py` 位于 tencent-docs 插件目录（`C:\Users\Administrator\.workbuddy\plugins\cache\workbuddy-builtin\tencent-docs-plugin\*\skills\tencent-docs\`，版本号随插件升级变化），可用 `python3 tencentdocs.py tdoc_call <service> <method> '<json>'` 调用；或直接在 Python 里 `from tencentdocs import call_tool`
- Pillow：图片拼图需要，`python3 -m pip install Pillow`
- 沙箱注意：`/tmp` 目录不可写、`curl` 写文件异常，统一用 Python `urllib` 下载、写文件到工作目录

## 工作流

### Step 1: 读表格拿链接

> **⚠️ sheet_id 别猜（2026-09-18 踩坑）**：表格 sheet_id **不是** `000001` 之类的固定值。
> 传错会报 `get cell data by range error … missing data not found` 或
> `cannot find worksheet by sheet id`。**先查真实 sheet_id**：
> ```
> python3 tencentdocs.py tdoc_call tencent-docs sheet.get_sheet_info '{"file_id":"<FILE_ID>"}'
> # → sheets[0].sheet_id（如 BB08J2）、sheet_name、row_count、col_count
> ```
> `sheet.get_sheet_info` 走 **tencent-docs 主服务**，不在 `sheet-mcp` 里（`get_sheet_meta` 不存在）。

用腾讯文档 sheet-mcp 读取「链接」列及「账号ID/车型/序号」列：

```
python3 tencentdocs.py tdoc_call sheet-mcp get_cell_data '{"file_id":"<FILE_ID>","sheet_id":"000001","start_row":1,"start_col":0,"end_row":44,"end_col":4,"return_csv":true}'
```

把结果整理成 rows 数组：`[(seq, acct, car, url), ...]`，保存为 `data/rows.json`（脚本统一输入格式，见 scripts 约定）。

> **⚠️ 行号定位铁律（2026-09 踩坑）**：表格**没有表头行**（第 0 行就是数据），且**序号不连续**（中间会缺号，如缺 160）。
> **禁止用 `row = seq - 起始序号` 推算**——缺号后整段错位，会写到别人行上。
> 正确做法：**先读序号列（col0）全列，按实际值建 `seq → row` 映射再写**。写前必须逐格复核目标单元格当前值。

> **⚠️ 调用通道**：腾讯文档 MCP 工具可能不在延迟工具索引里（ToolSearch 搜不到 `mcp__tencent-docs__*`）。
> 此时走本地 CLI：`python3 <插件目录>/skills/tencent-docs/tencentdocs.py tdoc_call sheet-mcp <工具> '<JSON参数>'`
> 常用：`get_cell_data`（读）、`set_range_value`（批量写）、`set_cell_style`（标色）。
> 参数结构用 `tdoc_schema sheet-mcp <工具>` 查，勿猜。
> 注意：`get_cell_data` 用 `return_csv:false` 读**多格区域**时 `cells` 常返回空，读单格正常；建映射请用 `return_csv:true` 解析第一列。

### Step 2: 打开链接（一窗口 10 个）

运行 `scripts/open_links.py`（或直接构造命令）。核心：每批 10 个 URL 用一次 `chrome.exe --new-window URL1 URL2 ... URL10`，43 个分 5 批。Chrome 需在运行中（`--new-window` 会把已有标签合并，提示用户可选先关其他窗口）。

### Step 3: 下载 HTML 快照（关键坑 — 方案已换代，2026-09 验证）

**懂车帝口碑页是 JS 渲染 + 需登录态。** 且从 Chrome 127+ 起 Cookie 走 **App-Bound Encryption**（`encrypted_value` 前缀 `v20`），密钥由**系统级 elevation 服务**托管，因此：

| 旧方案 | 状态 |
|---|---|
| `--headless=new` + `--dump-dom` 复用登录态 | ❌ 作废：拿到约 4.8KB「懂车帝-统一登录」壳页 |
| `chrome_cookies.py` 解密 Cookie 后走 HTTP 请求 | ❌ 作废：v20 解密报 `InvalidTag`，密钥链不匹配 |
| `check_login.py` 判定登录态 | ⚠️ 仅按 Cookie **字段名**判断，无 session 时也会误报「已登录」，**不可作为唯一依据** |
| **有头 Chrome + CDP 驱动** | ✅ **现行方案**：由 Chrome 自己持有并解密登录态 |

**为什么必须「非默认路径 + 有头」**（两条硬约束，缺一不可）：
1. Chrome 在**默认 user-data-dir** 下会**忽略 `--remote-debugging-port`**（端口不监听）→ 必须用非默认目录
2. **无头模式拿不到 App-Bound 密钥**（不在同一会话/服务上下文）→ 必须有头
3. 用法：把登录态所在 profile **完整复制到纯 ASCII 非默认路径**，用该副本启动有头 Chrome
   - `--user-data-dir` **不能含中文**（本机用户名含中文，直接指向原目录会 0 字节/复用失败）
   - 源路径含中文无妨，仅目标路径需 ASCII（如 `D:\kbd_ud`）

**一次性准备（每环境一次，之后长期复用）**
1. 复制 profile：`data/copy_profile3.py` —— 复制根级 `Local State`（ABE 主密钥容器）+ 整个 profile 目录；排除 `Cache`/`Code Cache`/`GPUCache`/`Extensions` 等可再生目录。**`Local State` 与 Cookies 必须成对复制**，否则会话失效
2. 用户在**副本窗口**登录懂车帝（专用自动化 profile，与日常浏览器隔离，不干扰用户）
   - 启动登录窗口：后台运行 `node data/launch_login.js`（有头、带 `--remote-debugging-port`、打开 `https://www.dongchedi.com/`）
   - **Node 启动脚本必须常驻**（`setInterval` 保活或后台任务），否则沙箱随前台命令结束回收 Chrome
3. 登录后确认窗口**保持打开**（后续批抓直接复用该实例的调试端口）

**批抓（`data/cdp_batch.js`）**
```
node cdp_batch.js 9333 "D:\kbd_ud" "Profile 3" all 0
# 参数：<端口> <user-data-dir> <profile名> <条数|all> [起始下标]
```
- 端口已监听则**复用现有实例**（不再 spawn），否则自行启动有头 Chrome
- 必须 `Network.setUserAgentOverride` 设 iPhone UA + `Emulation.setDeviceMetricsOverride` 移动视口，**否则 `m.dongchedi.com` 被重定向到桌面首页**
- 逐条 `Page.navigate` → 轮询 `document.getElementById('__NEXT_DATA__').textContent`（约 15-20s/条）→ 落盘 `html_snapshots/kb_<seq>.json`
- 数据落盘后**不再需要 Chrome**，提取与图片下载均为纯本地操作

**校验口径（务必查这三个信号）**
- `cookies=N hasSessionCookie=true` ← 登录态有效
- `page === '/ugc-article'` 且 JSON > 10KB ← 真实口碑页
- `page === '/new_home'` 或 `asPath === '/'` ← 被跳首页（登录态失效或 UA 不对）
- `isLoggedIn` 字段在 `/ugc-article` 页可能为 `undefined`，**不要**据此判失败

### Step 4: 提取标题/评分/发布日期

从 HTML 的 `<script id="__NEXT_DATA__" type="application/json">` 解析 JSON，路径：

- 评分：`articleDetail.car_view.score`（整数 0-500，÷100 = 5分制，如 380→3.80）
- 发布日期：`articleDetail.content_publish_time`（Unix 时间戳）
- 标题：`<title>` 标签去掉 `_懂车帝` 后缀；或 `motor_title` 正文第一句，去掉所有开头的 `【xxx】` 标记
- **正文全文**：`articleDetail.motor_title`（含 `【驾驶感受】`/`【最满意】` 等小点；注意 `articleDetail.content` 通常为**空串**，勿用）
- **原图直链**：`articleDetail.image_urls[].url`（数组，每项 `{url,width,height}`；URL 带签名 `x-expires`，**须尽快下载**，过期失效）
- 昵称：`articleDetail.motor_profile_info.name`；车型：`articleDetail.motor_car_info.series_name`

用 `scripts/extract_koubei.py` 批量提取，输出 `data/extracted.json`（seq → {title, score, date, car}）。

**附带模式：下载图片和文案（素材归档）**

当用户说「下载图片和文案」时，目标是**每篇口碑一个文件夹：正文 txt + 全部原图**。用 `data/extract_all.py`：

- 输入：`html_snapshots/kb_<seq>.json` + `data/rows.json`（seq/acct/car/url）
- 输出：`out/<seq>_<昵称>/文案.txt`（含序号/昵称/车型/正文/图片数/来源链接）+ `img_01.jpg ... img_0N.jpg`
- 图片下载用 Python `urllib`，带 `User-Agent`(iPhone) + `Referer: https://m.dongchedi.com/`；小于 1KB 判为失败
- 完成后 PowerShell `Compress-Archive` 打包 zip 交付（**present_files 只能传文件、不能传文件夹，必须打包**）
- 典型规模：22 篇 × 4 图 ≈ 15MB；正文约 430-500 字/篇

### Step 5: 写回表格

用 `scripts/writeback_sheet.py` 通用写回。API 关键格式（极易踩坑，务必遵守）：

```python
from tencentdocs import call_tool
def call_safe(service, method, params):
    r = call_tool(service, method, params)   # 返回 tuple (response_dict, _)
    return r[0] if isinstance(r, tuple) else r

# 写值：set_range_value 用 values 数组（每项 {row, col, value_type, string_value}），
#       不是 start_row/end_row 参数！
call_safe("sheet-mcp", "set_range_value", {
    "file_id": FILE_ID, "sheet_id": SHEET_ID,
    "values": [{"row": 1, "col": 7, "value_type": "STRING", "string_value": "3.80"}],
})
# 标色：set_cell_style 用 start_row/start_col/end_row/end_col + font_color/bg_color（ARGB，A在前）
call_safe("sheet-mcp", "set_cell_style", {
    "file_id": FILE_ID, "sheet_id": SHEET_ID,
    "start_row": 1, "start_col": 7, "end_row": 1, "end_col": 7,
    "font_color": "FFFF0000", "bg_color": "FFFCEBEB", "bold": True,
})
```

- 评分列写两位小数字符串（"3.80"），避免数值类型丢精度
- 批量写值建议每批 ≤15 条，避免超限

### Step 6: 评分区间核实

车型 → 打分区间映射见 `references/车型区间映射.md`（可变，按实际车型更新）。比对每条评分是否落在区间内，生成「符合/不符合」判定。


### Step 7: 图片要求核实（视觉辨认，四条规则）

| 规则            | 判定内容                                                             | 比对基准                                       |
| ------------- | ---------------------------------------------------------------- | ------------------------------------------ |
| **R1** 基础规则   | 至少一张**合格车身照**（完整车身 / 车头 / 车尾，定义见 7.3）、不能全内饰、不能出现人物               | 纯视觉判断                                      |
| **R2** 车型外观一致 | 口碑中的**车身外观** = 表格声明的官方车型（是否符合官方车型）                               | 汽车之家该车型**官方图**                             |
| **R3** 颜色统一   | **车身颜色统一**：口碑各张外观图车身漆面色一致；**内饰图片统一**：口碑各张内饰图配色/款式一致（同一辆车只能有一套内饰） | 纯视觉判断（同篇横向互比，不与官方图比；展厅车外观图同样参与，内饰氛围灯/玻璃反光不算车身色差异） |
| **R4** 图文颜色一致 | **图片颜色 = 文章写的外观/内饰颜色**（正文说"白外黑内"，图里就须是白车身 + 黑内饰）                 | 图（视觉）vs 口碑正文外观/内饰颜色描述（文本）                  |

#### 7.1 抓汽车之家官方参考图（R2 车型比对的基准，**最先做**）

每个涉及的车型跑一次：

```
python3 scripts/fetch_autohome_refs.py "星光560-燃油版" refs 12
python3 scripts/fetch_autohome_refs.py --series 5050 refs 12     # 已知 ID 时直给
```

- series ID 优先从 `references/汽车之家车型对照.md` 读；表里为空则走 `sou.autohome.com.cn` 搜索兜底
- 输出 `refs/<车型>.jpg`（官方外观图纵向联系图，带编号标签）；确认过的 ID 缓存到 `data/autohome_series.json`
- **抓完先 Read 一遍 `refs/<车型>.jpg`，确认车型没抓错再往下跑** —— 基准错 = 整批判定全废
- 反爬要点：PC 版 UA + `Referer: https://www.autohome.com.cn/<id>/`；图片 CDN 为 `carN.autoimg.cn/cardfs/product/`
- 图页分类：`<series>/1.html` 车身外观、`12` 中控方向盘、`13` 车厢座椅

#### 7.2 口碑图 → 联系图

1. 从 HTML 的 `image_urls` 数组（每项 `{url, width, height, img_type}`，`img_type` 恒为 1 无分类价值，必须视觉判断）取 CDN 签名 URL（`p3-sign.toutiaoimg.com`）
2. 下载：Python urllib + 请求头 `Referer: https://m.dongchedi.com/` + iPhone UA（curl 会失败/0字节）
3. 用 `scripts/download_contact_sheets.py` 下载全部图片并用 Pillow 拼成每页一张「联系图」（单列纵向，带编号标签），输出 `sheets/<seq>.jpg`

#### 7.3 逐页五问视觉比对（R1-R4 四规则）

Read `sheets/<seq>.jpg`，**同时对照该条声明车型对应的 `refs/<车型>.jpg`**（官方图只用于第 3 问车型比对），逐页判 5 个问题：

1. **有合格的车身照吗**？(R1)「合格车身照」= 完整车身、或**车头**、或**车尾**，能看清整体造型、可作为 R2 车型判定的依据。
   - ✅ 算合格：整车侧面/斜前/斜后全景、正前脸、正车尾
   - ❌ 不算合格：只有**局部细节特写**（单拍轮毂 / 大灯 / 门把手 / 后视镜 / 尾标 / 格栅局部）、车内视角、只透过挡风玻璃露出一小截机盖
2. **有没有人物出现**？(R1) 按出现程度分级（**核心修订**）：
   - **🟢 无人物**：完全干净，无任何人类元素。
   - **🟡 轻度暴露 / 可忽略**（**判符合**，**不视为 R1 不通过**，但备注里写清「图X 出现XXX」）—— 常见可忽略情形：
     - 方向盘区域露出的手指/手臂局部（车主刚拍完下车）
     - 仪表盘或中控位置的手指（按键操作）
     - 车外背景中的行*人、路人（非主体）*
     - *玻璃/漆面反光中可见的模糊人影*
     - *完整车身照里驾驶位是玩偶/摆件（不是真人）*
     - *单张角落里的*手指甲/手指尖
   - **🔴 真实人物主体**（**判 `含人物` 不符合**）—— 真实完整可见的人物占据画面主体，例如：
     - 完整坐姿的驾驶员/乘客（脸或半身明显）
     - 后排儿童/家人完整可见
     - 车内维修人员/拍摄者本人完全入镜
   - **判定要点**：看人是否为主体 / 是否占画面显著比例 / 是否完整可见；模糊远景里的"疑似人形"按 🟡 处理；拿不准一律按 🟡（判符合 + 备注），不升级到 🔴
3. **车型吻合吗**？(R2) 逐项对齐官方图：
   - 前脸：格栅造型（燃油/新能源格栅常不同，按声明版本比）、大灯轮廓与灯组、日行灯位置
   - 侧面：车身比例、腰线走向、门把手（隐藏式/外露）、轮毂样式、充电口盖有无
   - 尾部：尾灯造型（贯穿式/分体）、尾门线条、后保险杠
   - 判定前提：先有合格车身照（完整车身/车头/车尾）才有资格谈 R2；全是局部特写 → R2 判 `待确认`（`车型存疑`），不硬判
   - 只要关键特征有一处明显对不上 → 判 `车型不符`
4. **颜色统一吗**？(R3) —— 分**外观**与**内饰**两侧各自统一，不跟官方图比颜色（核心修订）：
   - **外观侧 · 车身漆面色统一**（**车身颜色要统一**）：
     - **比的是「车身漆面色」**：口碑内全部外观图（**含展厅场景拍摄的车**）横向互比，车身漆面色一致即可；**内饰氛围灯、玻璃反光不参与车身色判定**——展厅里同款不同色车不再豁免，同样计入颜色差异证据。
     - **判定证据**：选所有**外观图**（含合格车身照、车头/车尾、局部车身特写）；**内饰图、车内氛围灯、玻璃反光、天幕、轮毂样式图不参与车身色判定**。
     - **不统一**（**判 `颜色不统一` 不符合**）：口碑内 2 张及以上的外观图车身漆面色明显不同（例：图1 银色车身 vs 图5 白色车身；图1 棕色车主原车 vs 图3 白色展厅车——展厅车外观图同样参与判定，颜色对不上同样判不统一）。
     - **🟡 拿不准 → `颜色存疑`**（**判待确认**，不判不符合）：夜景强光、严重侧光、滤镜偏色、整组都是展厅白底翻拍时。
   - **内饰侧 · 内饰配色统一**（**内饰图片要统一**，核心修订）：
     - **比的是座椅/门板/中控的主配色与款式**：口碑内所有**内饰图**横向互比，同一辆车只能有一套内饰（例：全组黑内、或全组米内/棕内），风格、缝线、材质走向应一致。
     - **判定证据**：所有内饰图（中控方向盘、车厢座椅、门板特写等）；**仪表盘亮起时的屏幕颜色/氛围灯颜色不参与内饰配色判定**（氛围灯可变色，不算差异）。
     - **不统一**（**判 `内饰不统一` 不符合**）：2 张及以上内饰图出现明显不同配色（例：图2 黑内 vs 图4 米内；图1 棕内 vs 图5 黑内）——同一台车不可能两套内饰，拼接盗图嫌疑。
     - **🟡 拿不准 → `内饰配色存疑`**（**判待确认**，不判不符合）：同一色系因光线/角度观感不同、图太暗看不清时。
   - 注意：同一台车日间/夜景/侧光下观感会不同，只在同侧内颜色明显对不上时才判不统一。
5. **图文颜色一致吗**？(R4) —— **图片颜色要和文章写的外观/内饰颜色一样**（核心新增）：
   - **正文颜色词来源**：从已下载口碑 HTML 的正文段落（【外观】【内饰】【最满意】等小点的文字）提取外观色/内饰色描述（白/黑/灰/银/蓝/青/紫/红/棕/米/橙/金等，或「XX色」），**不凭标题或表格内容臆断**；需要时先 Read/文本提取正文对应段落
   - **一致 = 通过**：正文写「白外黑内」，外观图车身是白色、内饰图主配色是黑色 → 通过；正文只写了外观色或只写了内饰色，则只核写了的那一侧
   - **图文颜色不符**（**判 `图文颜色不符` 不符合**）：正文明确写了某侧颜色，而对应图明显是另一种颜色（例：正文「珍珠白/青绿外观」，外观图却是银色或黑色车身；正文「黑内」，内饰图却是米内/棕内）
   - 正文**没提任何颜色** → R4 **不适用，不判**（通过，不算不符合）
   - **🟡 拿不准 → `图文颜色存疑`**（**判待确认**，不硬判）：图严重偏色/滤镜/强光看不出真实色、正文颜色词含糊（如「双拼」「马卡龙色」无明确主色）时

#### 7.4 判定与写回

- `符合` = R1 ∧ R2 ∧ R3 ∧ R4 全部通过
- `不符合` 时用下列标签（多个并存用 `+` 连接，按出现顺序拼接）：
  | 标签        | 规则 | 含义                                                                                                                      |
  | --------- | -- | ----------------------------------------------------------------------------------------------------------------------- |
  | `含人物`     | R1 | **真实完整可见的人物**主体占据画面（坐姿完整的人、车后座家人、儿童完全可见、维修人员入镜）。**轻度人物暴露（手指、玩偶、背景路人、玻璃反光、角落手指）判符合，不挂这个标签**——但是要在备注里写清楚「图X 出现 XXX | 没问题」 |
  | `全部内饰无车身` | R1 | 全是内饰，无任何外观照                                                                                                             |
  | `仅有局部特写`  | R1 | 有外观图但全是局部细节（轮毂/大灯等），无完整车身/车头/车尾                                                                                         |
  | `车型不符`    | R2 | 图里的车与声明车型不一致（车身外观不符合官方车型）                                                                                               |
  | `颜色不统一`   | R3 | 口碑内**车主原车的车身漆面色**出现 2 种以上明显不同（拼凑盗图嫌疑）。**不与内饰氛围灯、玻璃反光比较**                                                            |

  | `图文颜色不符`  | R4 | 口碑正文明确写了外观/内饰颜色，而对应图片明显是另一种颜色（例：正文「白外黑内」vs 图里银车身/米内）                                                                    |
- **拿不准时不要硬判**，写 `待确认` 而非 `不符合`：`车型存疑`（角度差/太暗/只有局部）、`颜色存疑`（夜景/侧光/滤镜偏色、整组都是展厅白底翻拍拿不准）、`内饰配色存疑`（同色系光线差异/图太暗）、`图文颜色存疑`（图偏色看不出真实色、正文颜色词含糊）
- **R1 人物分级判例**（来自用户复核的真实样本）：
  - 🟢 判符合（备注里仍要说明）：「图3 驾驶员手臂握方向盘」「图4 左侧出现手臂/手部」「图1 背景中斑马线旁可见站立路人」「图2 玻璃反光中出现人影」「图2/5 完整车尾画面左侧出现指向车的手指」「图1/5 内饰中央扶手出现人物腿部(牛仔裤)」「图1 仪表盘手 + 图3 内饰手」「图2/5 完整车身斜前画面含驾驶员人物 但这是玩偶」 → 全部判符合，备注写清现象
  - 🔴 判 `含人物` 不符合：完整坐姿的真人驾驶员（脸/半身明显）、后排完整可见的家人/儿童、车内拍摄者本人完全入镜；样本中无此严重情形

### Step 8: 发布文章间重复核实（写回「是否重复」列）

**发布的文章之间是否有重复**（2026-09-09 用户定稿，从"同人同车去重"升级为"整表文章互查"）。跑完 R1/R2/R3/R4 后，检查范围不限于同一作者：批量创作脚本（koubei-batch-create）很容易出现「同一账号+同车型+N 篇模板化口碑」，也可能出现跨账号互相复制、只改车型名/人设头尾就重复投稿，需要识别并打标。

#### 8.1 判定规则（按优先级命中即停）

1. **链接级重复**：URL 完全相同 → `是(url)`
2. **账号+车型级重复**：同一 `账号 ID` + 同一 `车型` 出现 ≥2 次 → `是(同人同车)`
3. **标题强相似**：两篇口碑标题前 30 字重合度 ≥80%（剔除首尾人称/称谓后做最长公共子串 / Jaccard / 编辑距离三种里任一）→ `是(标题相似)`
4. **正文强相似**（新增）：两篇口碑**正文**（去标点、剔除【小点】标题与首尾人设/购车背景句后）归一化相似度 ≥85%（最长公共子串占比 / 连续相同片段 ≥60 字）→ `是(内容重复)` —— **不限于同账号，跨账号正文大段复制同样命中**（例：同一篇正文只改车型名和人设头尾就发两条）
5. **图片签名重复**（可选，必要时）：两篇口碑的「联系图」主色块分布/MD5 异常一致 → 标记 `待确认(疑似盗图)`，**不直接判重**，人工再核实

命中 1-4 任一即视为重复，**直接写入「是否重复」列**（注意本列在表头位置依实际布局，**先读表头确认列号**再写，**不要硬编码**）。

#### 8.2 写回格式

| 列         | 值                                                        |
| --------- | -------------------------------------------------------- |
| 「是否重复」列   | `是` / `是(同人同车)` / `是(标题相似)` / `是(内容重复)` / `是(url)` / `否` |
| 「备注」列（追加） | 已有备注后追加 `\|重复：<简述>`（例：`\|重复：与第3行同人同车`、`\|重复：与第7行正文大段相同`） |

- 标色：`是`/`是(...)` 与表头「是否重复」单元格同色标**红字 + 浅红底**（`font_color=FFC00000` + `bg_color=FFFEEFEF` + bold）；`否` 默认样式不变
- 「同人同车/内容重复」是重复出现的客观事实，**不等于该篇内容无效**——批量创作流水线常故意产 N 篇同作者同车型口碑，只要人工标好、内容确有差异，不影响后续用

#### 8.3 「如何避免误伤」

- 同账号不同车型 → **不算重复**
- 同车型不同账号 → 标题/正文都不同 → **不算重复**
- 同账号同车型但 **标题/链接/内容完全不同** → 不算重复
- 同账号发 N 篇「不同场景/不同背景/不同人设」的口碑 → **只要标题与正文都不撞，就算合格的不同篇**（常见批量创作场景，允许）
- 警惕 false positive：正文判重以归一化相似度 ≥85% 或连续 ≥60 字相同为门槛，**同车型模板创作但正文场景/人设/细节不同 → 不算重复**；只有标题前 30 字强相似 或 正文大面积复制 才打标


### Step 9: 文章参数与官方一致核实（写回备注/参数核实列）

**文章中的各种参数是否与官方的一致**（2026-09-09 用户定稿，防硬伤底线）。比对基准 = **官方参数**：汽车之家该车型官方参数配置页 / 官方公布数据；`koubei-batch-create` 的 `references/车型事实库.md` 已核实过的参数可直接复用，未覆盖的新车型先 WebSearch 官方口径再判。

#### 9.1 参数提取与分类

从文章正文提取出现过的数字/规格参数，按类核对：

- **价格**：指导价 / 落地价 / 优惠幅度（**只设下界**：报价 ≥ 官方价×30% 即算合理，地区优惠 / 价格战 / 特价渠道都放行；「九万出头」「八万八落地」等模糊口语口径不算不符）
- **动力**：排量 / 电机功率 / 马力扭矩 / **动力类型**（燃油/纯电/插混写反 = 硬伤，直接不符）
- **能耗**：CLTC 续航 / 综合油耗 / 亏电油耗 / 电池容量
- **尺寸结构**：长宽高 / 轴距 / 座位数 / 后备箱容积（例：4 座车写 5 座 = 不符）
- **配置**：屏幕尺寸 / 全景影像 / 外放电 / 快充时间等 有无（有→无、无→有 写反 = 不符）

#### 9.2 判定

- **`参数一致`**：文章数字与官方一致，或在官方配置/公布数据的正常波动范围内（价格受地区/时间影响）
- **`参数不符`**（不符合，写回备注）：关键参数**往有利方向吹过头**或**结构写反**才判，备注写清「文章写 X（如续航 500km），官方为 Y（CLTC 430km）」
  - **方向性单边口径（2026-09-09 用户定稿，只判"过头/吹牛"，不判"打折/真实"）**：
    - **续航**：文章写 **> 官方** → 判不符（实际开不出，浮夸吹高）；文章 ≤ 官方 → **不判**（真实续航打折是常态）
    - **油耗/能耗**：文章写 **< 官方** → 判不符（实际达不到，理想化）；文章 ≥ 官方 → **不判**（实际油耗高于官方标称是常态）
    - **价格**：**只设下界**——报价 ≥ 官方价×30% 一律放行（地区优惠 / 价格战 / 特价渠道都算合理波动）；报价 **< 官方价×30%**（官方 10 万写 3 万以下）→ 一眼假，判不符
    - **结构硬伤（无条件判，不设幅度）**：动力类型 / 座位数 / 排量 / 配置有无 写反（燃油↔纯电、4 座写 5 座、有↔无）
  - 方向合理且在官方正常波动内（温度 / 路况 / 驾驶习惯 / 促销）→ 不算
- **`待确认`**：官方未公布 / WebSearch 查不到该数字 → 不编造"官方值"，写 `待确认(官方未公布)`，不做 `参数不符` 硬判
- **版本前提**：按表格声明的车型版本（2026 款燃油/新能源、高低配）对官方参数，**不同版本参数不同，严禁跨版本比对**

#### 9.3 写回

- 命中 `参数不符`：备注追加 `|参数：文章<参数X> vs 官方<参数Y>`；表格有「参数核实」列则标橙红/写值，**先读表头确认列号再写，不硬编码**
- 拿不准 / 官方未公布 → 备注写 `|参数：<参数>待确认`，不硬判不符


## 质量红线

1. 下载 HTML 走「**有头 Chrome + CDP + 非默认 ASCII profile**」方案（见 Step 3）；无头模式与 Python 解密 Cookie 在 Chrome 127+（App-Bound 加密）上已失效
2. 判真实内容看 `page === '/ugc-article'` 且 JSON > 10KB；`page === '/new_home'`/`asPath === '/'` = 被跳首页（登录态失效或 UA 不对）；不要只靠文件大小或 `<title>`
3. 评分 ÷100 两位小数；发布时间用 `content_publish_time` 而非表格旧值（旧值常按批次填错）
4. 写表格 API：`set_range_value` 用 `values` 数组格式，`set_cell_style` 用 `font_color`/`bg_color`（不是 textColor/fill）
5. 图片核实靠视觉 Read，不能靠 `img_type` 或文件名判断；**R1 人物判定按严重程度分级**：轻度暴露（手指/玩偶/背景路人/反光/角落指尖）→ 判符合 + 备注说明；真实完整可见的人物主体 → 判 `含人物` 不符合；不要把轻度暴露一刀切判 `含人物`
6. **车型核实(R2)必须以汽车之家官方图为基准**，不能凭印象判断；官方图车型一旦抓错，该车型整批判定作废 → 抓完先 Read `refs/<车型>.jpg` 确认车型正确，再批量比对。**颜色核实(R3/R4)不做官方图比对**，只横向比口碑自己的车身漆面色与内饰配色
7. **R3 拆两侧判、互不牵连**：外观侧只看**车身漆面色**（展厅场景外观图同样参与比对；内饰氛围灯、玻璃反光、漆面高光投影、轮毂样式图不参与），内饰侧只看**内饰配色与款式**（氛围灯可变色不参与）；每侧只在同侧图明显对不上时才判不统一（`颜色不统一` / `内饰不统一`）；拿不准一律写 `待确认`，不判 `不符合`
8. 同车型不同版本（燃油/新能源、高低配）外观细节可能不同，车型比对要按表格声明的具体版本找对应官方图
9. **「是否重复」**判定必须基于客观信号（链接 / 账号+车型 / 标题强相似），不靠猜测；同账号同车型不算"内容无效"，批量创作脚本常故意产 N 篇同名同车口碑，只要标题不撞就放过
10. **R4 图文颜色必须互证**：正文颜色词从口碑正文（【外观】【内饰】等段落）提取，不凭标题/表格臆断；正文没提颜色 → R4 不适用不判；正文明确写了外观/内饰颜色而对应图片明显是另一种颜色 → 判 `图文颜色不符`；图偏色/颜色词含糊（双拼、马卡龙等）→ `图文颜色存疑` 待确认，不硬判
11. **文章重复核实是全表互查**：不限于同账号——跨账号正文大段复制（归一化相似 ≥85% / 连续 ≥60 字相同）同样判 `是(内容重复)`；但同车型不同场景/人设/细节的正文不判重，防误伤
12. **参数核实按声明版本对官方数据，方向性单边判（只判"过头"不判"打折"）**：续航写 **> 官方**、油耗写 **< 官方** = 浮夸吹高 → `参数不符`；续航 ≤ 官方、油耗 ≥ 官方（真实打折常态）→ 不判；价格只设下界 **报价 < 官方价×30%**（官方 10 万写 3 万以下）才判不符，其余放行；动力类型/座位数/排量/配置有无 写反 = 硬伤直接判；官方未公布 → `待确认(官方未公布)`，绝不编造"官方值"
13. **座位数是硬伤项，优先核**：增程/SUV 常见虚增座位（如 iCAR V27 官方全系 5 门 5 座，口碑写"六座/第三排"→ 直接判 `参数不符`）
14. **腾讯文档 API 直连会 `no_token`，必须走 CLI**：`python <tencent-docs>/tencentdocs.py tdoc_call <service> <method> '<json>'`；脚本内 `glob` 探测插件目录时用 `os.path.expanduser("~")`，**不要硬编码用户名**（本机用户名是中文，且不同机器不同）
