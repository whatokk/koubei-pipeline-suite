## 三种工作模式

### 模式 A:处理单份 HTML

输入:一个 HTML 文件路径(汽车之家口碑详情页另存为产物)

流程:
1. 用 `extract_koubei.py` 提取所有小点(最满意/最不满意/空间/驾驶感受/续航/外观/内饰/性价比/智能化…)
2. 从 HTML title 或文件路径解析「车型」(例如「星光730新能源 2026款 纯电 500km 尊享型」)
3. 从 HTML 提取「车主昵称」「口碑链接」「发布时间」填入数据来源
4. 各小点原文 upsert 进表作为素材(处理状态=「已改写」可留空改写后,或存原文)
5. **基于全部小点原文,写一篇完整口碑(小点=「整篇」)**:
   - 风格:车主口吻 | 平台:懂车帝
   - 总字数 300-800,用小标题分段(【最满意】【续航】【驾驶感受】【智能化】【最不满意】【总结】)
   - 每个观点挂原文论据,结尾给「适合谁」小结
6. upsert「整篇」记录(已存在则更新):填 改写后 / 改写说明 / 改写字数 / 处理状态=已改写
7. 汇报:提取几个小点 / 整篇多少字 / 成功或失败

### 模式 B:扫描表格里的「待改写」

输入:无(定时任务 / 用户手动触发)

流程:
1. `record-list` 查「处理状态 = 待改写」的所有记录(每次最多 20 条,超过分批)
2. **按(车型+数据来源)分组**,把同一篇口碑的各小点原文聚合起来
3. 每组写一篇完整口碑(小点=「整篇」):车主口吻/懂车帝/300-800字/小标题分段
4. upsert「整篇」记录:改写后 / 改写说明 / 改写字数 / 处理状态=已改写;组内各小点记录同时置为「已改写」
5. 单组失败:相关记录状态→「改写失败」,备注写失败原因,继续下一组
6. 全部处理完汇报:处理几组 / 成功几组 / 失败几组

### 模式 C:批量处理 HTML 文件夹

输入:一个目录路径(默认 `D:\口碑HTML\`)

流程:
1. 扫描目录下所有 `*.html` (汽车之家口碑页特征:title 含「口碑_汽车之家」)
2. 对每份 HTML 走模式 A 流程
3. 最后汇总:共处理几份 HTML / 新建几条口碑 / 跳过几条 / 成功几条 / 失败几条

## 核心产出形态(2026-07-22 用户定稿,最重要)

**最终交付 = 一篇完整口碑文章(小点=「整篇」),不是每个小点各一篇长文。**

- 把提取到的各小点(最满意/最不满意/空间/续航/驾驶感受/外观/内饰/性价比/智能化)**浓缩成一篇完整口碑**,用小标题分段
- **整篇总字数 300-800 字**
- 默认风格:**车主口吻**(真实、口语化、像真车主发帖)
- 默认平台:**懂车帝**
- 各小点的原文记录保留在表里作为素材库,不删;「整篇」记录的「原文」字段可留空或写"见同车型各小点"
- 字数分配参考(总 ~550-600 字):开头 30-50 / 最满意 120-180 / 续航 70-100 / 驾驶感受 60-90 / 智能化 70-110 / 最不满意 30-50 / 总结 50-90

## 改写规则(核心约束)

【质量三条铁律,优先级最高 — 2026-07-22 用户定稿】
1. **基于真实体验做评价和解读**,每个观点必须有原文里的论据支撑(具体数字/具体场景/具体细节),避免「空间大、续航好、性价比高」这种泛泛而谈的空话。
2. **评价客观平衡**:不过分吹(优点写得再好,结尾也要给适用人群建议),也不情绪黑(吐槽要就事论事,给出改进期待而不是发泄)。结尾带一句「值不值得买 / 适合谁」的小结。
3. **语言要像真实车主在说话**(口语化、有生活细节、有自己的节奏),**整篇总字数 300-800 字**。

【保留事实,这是底线】
- 所有具体数字必须保留:车型/年份/版本/公里数/续航CLTC/实测续航/车身尺寸/价格/充电时间/电价
- 主观评价保留(满意/不满意/吐槽点),不反着写
- 评分保持不变
- 不编造原文没有的功能、配置、数据

【懂车帝过审·真实车主风格 — 2026-07-22 补充,防「软文嫌疑」驳回】
背景:懂车分内容曾被懂车帝以「水军刷分、经销商推广、软文黑稿嫌疑」驳回。详见 `D:\项目\汽车之家\懂车帝过审风格-真实车主范.md`。
1. **开头有「人」**:素材有购车背景就写【购车经历】(旧车/动机/预算/对比车型/试驾下定);没有就用 1-2 句车主画像开头,绝不编造背景。
2. **有价必写【提车价格】**:指导价/优惠/落地/保险/上牌费,数字全保留——价格透明是真实帖最强信号。
3. **夸挂场景**:每个优点带具体数字或场景;鼓励优点里夹一个小缺点,不集中报喜。
4. **期望校准**:至少一处「这个价位就不追求 XX 了」式自我校准。
5. **缺点写法**:具体场景+受影响人群+改进期待,1-3 个,分散分布。
6. **克制带货腔**:拉满/闭眼入/吊打/真香 等营销词全篇 ≤1 处,优先删;多用生活化表达。
7. **结构**:开头(车主画像)→【购车经历】(有素材)→【提车价格】(有素材)→用车维度→【最满意】→【最不满意】→【总结:适合谁】。

## 改写说明字段写法

每条「改写说明」按以下模板填:
```
风格:<风格> | 平台:<平台>
保留:<具体保留了哪些关键事实/数字>
调整:<调整了哪些句式/语气/结构>
长度:原文 X 字 → 改写 Y 字
```

## 幂等和去重

- **记录级去重**:(车型 + 小点 + 数据来源) 三元组相同的记录不重复创建
- **状态机保护**:「改写中」状态的记录不会被并发任务重复处理
- **失败可重试**:「改写失败」状态的记录下次跑流水线时会重新尝试(不跳过)
