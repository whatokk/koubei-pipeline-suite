# Koubei Batch Create — 口碑批量创作流水线

> ⚠️ **平台边界（2026-09-24 加注，务必先读）**
> 本 skill 是 **懂车帝** 口径：小点 1~8 个随机组合、每篇 380-450 字、每 5 篇换一套模板。
> **写「汽车之家」口碑请改用 `autohome-koubei-write`** —— 汽车之家是平台表单固定 9 项小点、800-1100 字长文、不轮换模板，且要求**以官方配置页数据为写作依据并逐项核对**。
> 两套口径混用会直接翻车（小点数量、字数、模板轮换规则全都相反）。

## Overview

从车型清单直接批量创作车主口碑:核实车型事实 → 建事实库 → 设计人设 → 按「每篇2-3个小点随机组合」写作 → 脚本校验字数/结构 → 批量补写 → 交付Markdown。与 koubei-pipeline(改写已有素材)互补,本skill从零生成。

## 工作流

### Step 1: 确认需求

确认4项参数,缺省按默认值:
- 车型清单(默认沿用已核实过的六车型:缤果S / 第五代宏光MINIEV / 星光560燃油 / 星光560新能源 / 星光730燃油 / 星光730新能源)
- 每车型篇数(默认50,共300;2026-08-05 用户定稿从20改到50)
- 每篇字数(默认400字左右,即纯汉字380-450)
- 小点数量规则(默认「每篇1~8个随机 + 0~2段纯正文混排,每5篇换一套模板」,严禁连续篇同一种结构)

### Step 2: 核实事实(防硬伤,底线)

对每个车型用 WebSearch 核实 2026 款公开参数:价格区间/续航(CLTC)/电机或发动机动力/尺寸轴距/座位数/核心配置(大屏、全景影像、外放电等)/油耗。要点:
- 燃油版「续航」小点写作「油耗」,新能源写「续航」;插混写「纯电XXkm+综合XXkm+亏电油耗」
- 不确定的具体数字一律不写死(用「九万出头」「八万八落地」等模糊口径),绝不编造
- 已核实过的事实直接复用 `references/车型事实库.md`,无需重搜

### Step 3: 设计人设池

每车型50个不同人设(50篇时),跨车型尽量错开。参考人设池(可混搭):通勤上班族/宝妈/奶爸/应届生/退休夫妻/大学生/网约车司机/小店主/业务员/教师/医生护士/露营玩家/钓鱼佬/摄影师/程序员/民宿老板/果园主/驾校教练/返乡青年/小老板/多孩家庭/油转电车主…同一车型内50篇人设必须互不相同。

### Step 4: 写作(核心规则)

每篇结构 = 开头一句人设/购车背景(无标题) → 1~8 个【小点】分段 + 0~2 段纯正文(无标题,作过渡/场景延伸/补充说明)混排 → 自然收尾(可选一句小结,不套模板)。

小点写法:
- 每个小点 150-200 字:观点 + 具体数字/场景/对比,严禁「空间大、性价比高」式空话
- 数字挂场景:价格、续航达成、电费油费、尺寸、装载量等全部具体化
- 优点夹缺点、期望值校准(「这个价位就不追求XX了」),结尾自然(「值」「够用」),禁营销词(拉满/闭眼入/吊打/真香 全篇最多1处)
- 小点数量与顺序随机:有的篇【外观】开头,有的【最满意】开头;组合错开,如「外观+续航」「最满意+空间+不满意」「驾驶感受+智能化+性价比」;小点类型池含【不满意】【内饰】等负面/其他维度,不局限于最满意+空间+驾驶感受+油耗
- 模板动态轮换:每 5 篇换一套(50篇=10套),小点 1~8 个随机 + 纯正文段混排,严禁连续篇同一种结构
- 燃油版油耗:如「1.5T综合7.8,一箱油52升跑650公里」

### Step 5: 校验(必做,脚本)

运行 `scripts/check_koubei.py <文件路径>`,检查:
- 车型分节与每车型篇数是否达标
- 每篇纯汉字数(标准:380-450,含标点约470-550)
- 小点数量分布(2点/3点为主,不能出现5点以上)
- 同篇内重复小点标题(如两个【最满意】)
- 字数标注是否与实际一致

### Step 6: 批量补写(字数不足时)

若多数篇纯汉字 <370,说明小点没写透。**禁止用通用句池补写**(会跨篇重复18-29次,是"口碑雷同"的根源)。正确做法:
1. 按篇号绑定独特补写句(内容贴合该篇人设/主题,不与任何已写段落前30字重复)
2. 1~2小点模板篇字数天然不足 → 补1-2个贴合车型的补充小点(空间/续航/油耗/内饰/外观轮换)
3. 改合集源文件 → 重新 split 拆分(保持合集与成品一致),勿直接改拆分文件
4. 校验:字数380-470、小点1~8、纯正文0~2段、跨篇重复段落0、同篇小点不重复、【不满意】内不嵌正面句(结尾收尾句除外)

### Step 7: 交付

- 文件名递增:`六十篇口碑合集-v17(...).md`(沿用v14/v15/v16命名惯例),Markdown结构:`# 车型大标题` + `## N-人设(XXX字)`
- 用 present_files 交付;文本回复给结构一览表(车型×人设)与字数统计

### Step 8: 打包成品(每篇配一组图,2026-08-05 用户定稿)

成品 = 1 篇口碑 md + 1 组(5张)图,图片双尺寸(800x600 与 1280x960)。运行 `D:\项目\汽车之家\build_packages.py`:

```
python build_packages.py --model "<车型名>" --limit 50 \
  --imgs "<该车型 *_口碑_files 目录,多个逗号分隔>" \
  --mds "D:\项目\汽车之家\口碑成品\<车型名>"
```

- 脚本自动:双尺寸覆盖式居中裁剪(JPEG q90) → 每5张一组 → 与口碑txt按序配对
- 产出:`成品库\<车型>\成品01..N\` = `口碑.txt` + `800x600\01-05.jpg` + `1280x960\01-05.jpg`
- 组数 = min(图片数/5, 口碑篇数, 50);素材不足50组按实际生成并报告缺口
- 每车型默认 50 篇(用户定稿),图片需 ≥250 张(50成品×5张),优先1290x960左侧大图,不足补800x600及其他尺寸
- 打包后运行 `D:\项目\汽车之家\.workbuddy\scratch\verify_packages.py` 校验:每成品恰好 1 口碑 + 5 图双尺寸
- 成品库即最终交付形态,无需飞书入库

## 质量红线

1. 事实底线:所有数字必须核实或模糊化,不编造;保留车主主观评价
2. **模板动态轮换(2026-08-05 用户定稿):** 每5篇换一套模板(50篇=10套),小点 1~8 个随机 + 0~2 段纯正文(无【】标题,作过渡/场景延伸/补充说明)混排;带【】标题段落与纯正文段落交错,严禁连续篇同一种结构。小点类型池:最满意/不满意/空间/驾驶感受/油耗或续航/外观/内饰/性价比/智能化,随机组合,不局限于最满意+空间+驾驶感受+油耗
3. 字数按纯汉字计,脚本校验为准,不靠目测
4. 人设口吻必须不同,同一车型内避免句式模板化(开头句式、结尾句式都要错开)
5. 每篇 1~8 个小点均可(不再固定 2-3 个),小点 150-200 字带数字场景,优点夹缺点+期望校准,营销词≤1处

## 变体:短文案模式(50字左右,2026-09-12 新增)

触发场景:用户已有一批车型特点/口碑素材(如从真实口碑合集提炼的共性),要求「写N篇XX字以内的文案」「更像真实车主」,而非从零生成400字长口碑。与主流程的区别:

- **规格**:每篇总字符(去空格)45-70 字、纯汉字约 32-55(短文案里数字占比大,按总字符口径判断更贴近用户「50字左右」的感知);标注实际字符数便于用户核对;不分小点、不加标题,一段话到底
- **结构**:一句话场景/结论开头 → 体验+具体数字(1-2个参数或费用) → 一句缺点或自然收尾
- **口语词**:每篇≤1处,「哈哈/说实话/反正/贼/真」分散使用,同一词不连续两篇出现
- **参数**:仍走 `references/车型事实库.md` 核对;宁少勿编,不确定就用模糊口径;每篇至少带1个可核实的数字
- **差异化**:多篇之间按「人设+切入角度」错开(省钱/家用/动力/颜值/对比决策/越野/智驾/舒适等),避免同角度重复
- **红线**:不用营销词(拉满/闭眼入/吊打/绝绝子),允许1处主观情绪表达;缺点要真实存在,不硬造
